Design approach for the new tabs

Three ways to wire up Code Dissection, Manifest, dead IPs, obfuscated code, and decode. Pick the one that fits best.

A

Reuse what exists (recommended)

Plug the existing SmartDissection component into the Dissection tab, add a lightweight source viewer, and reuse the existing ObfuscationView for the Obfuscation tab. Manifest fetches the dissection endpoint; C2 tabs fetch threat-intel for status badges.

Pros

  • Fastest path
  • Uses tested components
  • Minimal backend changes

Cons

  • Class list may lag on huge APKs
  • Each tab fetches its own data
B

Shared data layer + package tree

Build a small React hook that loads dissection, manifest, and threat-intel once per sample. Render classes as a collapsible JavaScript-package tree. Source viewer lazily loads code only when a class is opened.

Pros

  • Fewer network requests
  • Easier to navigate large apps
  • Cleaner component boundaries

Cons

  • More frontend refactoring
  • Slightly longer design phase
C

Backend-enriched result

Move the work to the backend: embed full manifest, C2 status, and obfuscated-class markers directly into the pipeline result JSON. Frontend tabs just render what they already receive.

Pros

  • Simplest frontend code
  • Fewest API calls

Cons

  • Bigger pipeline result files
  • Requires backend changes
  • Harder to refresh a single tab later
