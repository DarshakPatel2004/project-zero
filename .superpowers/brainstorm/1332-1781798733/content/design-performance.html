Performance safeguards for Approach A

So the new tabs don't slow down the site, especially on large APKs.

1. Lazy tab loading

Each tab only fetches its data when the user opens it. The Overview tab loads instantly from the already-saved pipeline result. Dissection, Manifest, C2, and Obfuscation do not fetch anything until clicked.

2. Dissection tab: load classes in chunks

  • Render only the first 250 classes by default; add a "Load all" button for power users.
  • Default filter is Suspicious, which is usually a small subset.
  • Search is debounced so typing doesn't re-render on every keystroke.
  • Source code is fetched only when a class is clicked.

3. Manifest tab: small payload

Manifest data is tiny compared to class lists. No extra safeguards needed.

4. C2 tab: single lightweight call

Threat-intel endpoint returns only the C2 list + status/counts. No heavy computation in the request path.

5. Obfuscation tab: reuse component

The existing ObfuscationView fetches one summary object. It does not load decompiled source.

Fallback if a tab is still slow

If the Dissection tab lags after these safeguards, the next step would be to add virtualized scrolling (react-window) for the class list. That is out of scope for this pass but left as a clean upgrade path.
